# R26 连续采集固件 · v0.61

## v0.61 启动灯光（2026-11-05）

1. 进入Arduino应用程序的 `setup()` 后，**SYS和FAULT立即同时常亮**，随后初始化蓝牙与传感器任务。
2. 蓝牙服务、光学任务首次初始化/轮询、AFE任务首次ADC结果（或明确读取错误）完成后，两灯**同步闪烁5秒**：灭250ms、亮250ms，共10周期。
3. 闪烁结束才开始BLE广播、允许正常连接与采集；SYS恢复为笔尖按下亮/松开灭，FAULT恢复显示原有传感器与激励异常。

闪烁用定时状态机实现，传感器任务仍运行，不用 `delay(5000)` 卡住采集。启动阶段GSR关闭；之后仍只在电池供电、BLE主通道已订阅且检查通过时开启。

“初始化完成”指软件服务已启动并完成首次尝试，不等于全部传感器读数合格。未接IMU或其他传感器有错误时，仍可进入程序，通过FAULT和上位机查看具体状态；IMU波特率搜索继续进行。队列/任务分配失败时SYS灭、FAULT常亮，不广播、不允许激励。

此指示从应用程序入口开始，ROM启动和引导程序期间尚不能控制两灯。新程序烧录后，如果电池上电仍完全不亮而RESET后出现完整灯光流程，优先继续查应用之前的启动、供电/复位时序；如果双灯一直常亮，则优先定位初始化没有走完。指示本身不证明电源稳定，也不保证修复冷启动。

本次修正Arduino-ESP32 3.x GPIO写入顺序：预置输出锁存，配置OUTPUT后再执行digitalWrite；初始化阶段的高/低电平指令不会因引脚尚未注册被板包忽略。运行时只有主循环控制这两盏灯，传感器任务仅提交正常模式灯态，避免互相覆盖。

**已有v0.60上位机可以继续使用，本次只需重烧固件。**打开整个 `firmware/Pen_R26_Live` 文件夹里的ino，保留新增 `StartupLights.h` 及全部原有头文件；不要只复制ino。


打开 `Pen_R26_Live.ino`，所有 `.h` 留在同目录，使用本包配套Python。完整操作见[使用说明](../../software/PenLive/使用说明.md)。

按用户确认恢复有激励GSR：仅BLE主通道已订阅且USB未接入时启动；USB、断连、ADC/VEX异常均关闭。皮肤电和姿态与微动无关，启动灯光结束后SYS灯仍跟随微动。保留原有激励检查门限和USB硬件联锁。

- `opticalTask`：core1、优先级3，独占Wire/PAT，总线100kHz，轮询目标200Hz；连续累计位置、10ms微动消抖，产生带时间戳的轨迹点。
- `sensorTask`：core1、优先级2，独占AFE I²C、JY901S UART、ADC与GSR状态机；短周期非阻塞推进转换，GSR约10对/秒，姿态持续接收，电池显示约1Hz。
- Arduino loop：所有BLE发送的唯一入口，主遥测目标25Hz、轨迹批次目标50Hz，每批最多6点。独立任务通过队列和短临界区快照交换数据，不在临界区内操作I²C/UART/BLE。BLE底层沿用板包配置运行。

默认请求MTU185/15ms连接间隔；协商结果由主机决定。小MTU<105时位置发布目标50Hz、主遥测10Hz；实际读数仍200Hz目标并保持绝对坐标累积。队列256点，发送前积压超过24点时丢最旧点，并累计丢弃数；这是有损延迟限制，不是无损记录器。序号缺口由PC断线处理。

主通道9002是v4、90字节正文；9006是A6/version1轨迹分片。详见OpticalPacket.h。固件不平滑原始位移；电脑端可选平滑。9004/9005诊断的stroke字段在v4代表激励启动编号，与主笔画编号独立。

GPIO及接线均未改，JY901S不写配置，R408/R409/R410保持DNP，光学内部上拉保持关闭。NTC仍只能由充电芯片使用，不能读取数值。USB充电允许，标称电流仍由现板电阻设置。尚未实测新版本频率、功耗或续航；需要用户烧录验证。
