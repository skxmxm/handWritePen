# v0.61 启动灯光验证记录

2026-11-05。用户确认纯电池失败状态短按RESET可恢复；本版加入启动阶段显示，没有证明冷启动故障已修复。

- **实际Arduino编译通过**：本机3.2.1-cn板包，ESP32S3 Dev Module、Hardware CDC/JTAG、4MB、QSPI PSRAM、Huge APP；程序970,946字节，静态RAM49,292字节。日志 `reports/arduino_compile_v061.log`。
- **新增启动状态机C++测试通过**：初始化未完成保持双灯常亮；完成后灭250ms/亮250ms，同步10周期、逻辑计时5,000ms；正常灯态不抢占启动灯；结束后正确交还SYS/FAULT；32位毫秒回绕正确。日志 `reports/startup_lights_test.log`。物理闪烁的调度误差未实测。
- **底层API核对**：本机Arduino-ESP32 3.2.1-cn的esp32-hal-gpio.c要求pinMode注册后才能digitalWrite，已改为预置锁存→pinMode→digitalWrite。没有将此问题作为冷启动原因的已确认结论。
- **并发/激励核对**：setup先点亮两灯；任务只提交正常灯态，由主循环独占运行时LED输出。两个采集服务完成首轮结果后才闪灯；闪烁结束才广播/允许订阅；启动阶段GSR保持关闭，USB联锁、门限和状态机未改。
- **范围与兼容**：现有Python源文件及固件既有头文件共33份与v0.60哈希一致，新增StartupLights.h。v4传输协议不变，v0.60上位机可继续用；本轮无需重复UI/吞吐测试，下方80项Python等为v0.60历史结果。源文件比对和本轮验证摘要见 `reports/startup_validation_v061.json`。

闪灯表示应用的初始化流程已完成首次处理，不代表每个传感器健康。缺失传感器会在进入正常模式后通过FAULT及上位机反馈。队列/任务创建失败时SYS灭、FAULT常亮，激励关闭。若应用之前就卡在供电、ROM或复位阶段，软件无法点灯；本版没有自动重启或绕过保护。

本轮未烧录、未实物测试LED、首次电池启动或供电波形。交付前核验ZIP的CRC、文件内容、哈希与启动脚本执行权限；v0.60完整包已归档。当前源码/文档版本见 `reports/release_sha256.json`，本次压缩包校验在output目录的 `手写笔_R26_BLE_v061_包校验.json`。

## 平滑边界

采用确定随机种子的1000点合成静止噪声，轻度模式RMS小于原始55%；1000计数/秒合成匀速段延迟小于7计数（约7ms），拐角不越过输入坐标包络，松开端点回到原始值，断笔后滤波状态重置。这些是算法测试，不是传感器实测降噪百分比。关闭平滑时保持输入点一致。
