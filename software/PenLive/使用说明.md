# R26 连续采集优化版 · v0.61（启动灯光更新）

2026-11-05。本版按用户确认恢复有激励采集，**仅电池供电、蓝牙已连接并订阅时开启**。皮肤电和姿态持续显示，微动只决定画不画线，SYS灯仍跟随微动。USB接入、蓝牙断开或检查失败会关闭激励。换板后用户反馈恢复正常，电容损坏是用户推测，未独立确认。

**从v0.60升级，只需重新烧录固件，原v0.60上位机继续使用。**更旧版本需成套更新。当前版本包为 `手写笔_R26_BLE_v061_启动灯光版.zip`；连续采集优化版和通用文件名ZIP同步相同内容。旧的无激励说明是历史记录。


## v0.61 启动灯光（2026-11-05）

1. 进入Arduino应用程序的 `setup()` 后，**SYS和FAULT立即同时常亮**，随后初始化蓝牙与传感器任务。
2. 蓝牙服务、光学任务首次初始化/轮询、AFE任务首次ADC结果（或明确读取错误）完成后，两灯**同步闪烁5秒**：灭250ms、亮250ms，共10周期。
3. 闪烁结束才开始BLE广播、允许正常连接与采集；SYS恢复为笔尖按下亮/松开灭，FAULT恢复显示原有传感器与激励异常。

闪烁用定时状态机实现，传感器任务仍运行，不用 `delay(5000)` 卡住采集。启动阶段GSR关闭；之后仍只在电池供电、BLE主通道已订阅且检查通过时开启。

“初始化完成”指软件服务已启动并完成首次尝试，不等于全部传感器读数合格。未接IMU或其他传感器有错误时，仍可进入程序，通过FAULT和上位机查看具体状态；IMU波特率搜索继续进行。队列/任务分配失败时SYS灭、FAULT常亮，不广播、不允许激励。

此指示从应用程序入口开始，ROM启动和引导程序期间尚不能控制两灯。新程序烧录后，如果电池上电仍完全不亮而RESET后出现完整灯光流程，优先继续查应用之前的启动、供电/复位时序；如果双灯一直常亮，则优先定位初始化没有走完。指示本身不证明电源稳定，也不保证修复冷启动。

本次修正Arduino-ESP32 3.x GPIO写入顺序：预置输出锁存，配置OUTPUT后再执行digitalWrite；初始化阶段的高/低电平指令不会因引脚尚未注册被板包忽略。运行时只有主循环控制这两盏灯，传感器任务仅提交正常模式灯态，避免互相覆盖。

**已有v0.60上位机可以继续使用，本次只需重烧固件。**打开整个 `firmware/Pen_R26_Live` 文件夹里的ino，保留新增 `StartupLights.h` 及全部原有头文件；不要只复制ino。

## 1. 烧录与启动

1. 解压完整包，用Arduino IDE打开 `firmware/Pen_R26_Live/Pen_R26_Live.ino`，同目录全部 `.h` 文件保留，包括 `OpticalPacket.h` 和新增 `StartupLights.h`。
2. 安装Espressif ESP32板包。本机使用3.2.1编译；BLE、Wire随板包提供，无需安装旧版ESP32 BLE Arduino或其他传感器库。
3. 使用下表设置，选择USB端口上传。随后拔USB、接电池，必要时按RESET。
4. 关闭旧上位机。Mac双击本包 `software/PenLive/启动上位机.command`，Windows运行同目录 `.bat`。Python需带Tk，推荐3.12；首次可能联网安装bleak。macOS权限提示允许启动程序所属Terminal/Python使用蓝牙。
5. 等双灯常亮初始化及同步闪烁5秒结束，再扫描，选择SmartPen-R26，连接。无需在系统设置手动配对。
6. 不按笔尖也应看到空间姿态和皮肤电更新。按下画线，松开只移动光标并保留笔画；两个持续窗口不会被微动清空。

| Arduino IDE菜单 | 设置 |
|---|---|
| Board | ESP32S3 Dev Module |
| USB Mode | Hardware CDC and JTAG |
| USB CDC On Boot | Enabled |
| Upload Mode | UART0 / Hardware CDC |
| Flash Size | 4MB (32Mb) |
| Partition Scheme | Huge APP (3MB No OTA/1MB SPIFFS) |
| PSRAM | QSPI PSRAM |
| Flash Mode / Frequency | QIO / 80MHz，沿用板包默认 |
| Erase All Flash Before Sketch Upload | Disabled |

下载模式：按住BOOT/SW201，短按RESET/SW202，松开BOOT，再上传。固件不等待串口打开，拔USB后可独立启动。本次未自动上传到设备。

无硬件演示可双击 `演示界面.command`；窗口标有“模拟数据”，演示轨迹频率受UI驱动，不作为200Hz硬件性能测试。

## 2. 三个窗口的行为

| 状态 | 轨迹 | 空间姿态 | 皮肤电 |
|---|---|---|---|
| 电池＋蓝牙，笔尖按下 | 画线，SYS灯亮 | 持续显示 | 激励有效后持续显示 |
| 电池＋蓝牙，笔尖松开 | 空心光标移动，保留笔画 | 持续显示 | 持续显示，曲线不清空 |
| USB接入 | 仍可调试轨迹 | 持续显示 | 激励关闭，有效GSR暂停，不把0冒充测量 |
| 断开蓝牙 | 清空旧画板，等待重连 | 隐藏旧值 | 关闭激励、隐藏旧值 |
| 光学丢包/读取失败 | 缺口处断线，恢复后续画 | 不受光学错误直接控制 | 不受光学错误直接控制 |

“清空轨迹”只换新纸和坐标原点；“清空电压曲线”只清历史电压。“当前姿态归零”不需要按住笔尖。

USB连接时只做板上调试，取下指套；佩戴时使用拔USB后的电池供电。已有USB硬件联锁、激励电压范围和ADC故障检查全部保留，没有降低门限。

## 3. 轨迹平滑与刷新率

默认“轻度”平滑，也可选择“关闭”或“标准”。采用随速度变化的One Euro低通：低速减小抖动，快速运动减轻拖尾。原始坐标保留在内存，切换“关闭”会重绘当前历史的原始轨迹；滤波不改变固件累计位置，不跨抬笔/丢包缺口混合，明确的松开边界保留原始终点。它会引入少量延迟和圆角，无法修复传感器离焦、安装偏移或跟踪丢失。

光学轮询目标由100Hz提高到**200Hz**，每20ms发送一批，最多6个带时间戳的采样点。电脑每次绘图处理所有收到的新点，不只取最新位置。光学采集、其他传感器、BLE发送分别调度；蓝牙接收在后台线程，Tk只在主线程增量画图。界面调度目标60次/秒；不把调度次数当作显示器实际刷新或传感器实测频率。

页面底部的数字含义：

- **光学采集Hz：**固件光学轮询计数变化除以设备时间，包含读失败的尝试；同时看“光学正常”和缺口，不能只看频率。
- **到达点/秒：**电脑收到的完整轨迹采样数，批次不是点数。
- **界面次/秒：**UI调度频率，和BLE包率分开。
- **数据kB/s：**主遥测和轨迹通知的应用层字节数（含分片头），不含无线协议开销和独立诊断通知。
- **板端丢弃/电脑过期丢弃：**缓存拥堵时丢弃旧样本避免越画越滞后；缺失序号处断线，不补造中间路径。

协议小MTU（<105）时仍目标200Hz读取/累积位置，但只目标50Hz发送位置，并保留按下/松开边界；主遥测降为10Hz。大MTU下主遥测25Hz、轨迹约50批/秒、约200点/秒。实际连接参数由电脑协商，本程序不能保证所有电脑都达到目标。

原始轨迹为光学计数，尚未标定为毫米或补偿笔身倾角。反转Y默认打开，仍可交换XY、反转X/Y。自动缩放只在接近边缘时调整；关闭可固定比例。保留最近20,000个绘图记录（含断笔标记），约200点/秒连续书写时约100秒。抬笔移动本身不占绘图记录；未读到的悬空位移不推算。

## 4. 皮肤电与姿态的有效性

皮肤电大字号为ADS1115 A0/GSR_ADC板上输出mV，A1为VEX_MON，每计数0.125mV，A0/A1顺序转换，约10对/秒。只在激励稳定且ADC新鲜有效时显示GSR，重复采样不重复画曲线；USB、故障或过期时保留历史并留缺口。最多600条记录，正常约60秒。当前未标定为皮肤电导、电阻、两指电位差或压力分数。

激励检查：关闭至少100ms后VEX须在±50mV内；开启稳定300ms后须在350–700mV内（硬件名义约523mV）；ADC异常或超过500ms未更新关闭激励。故障后维持关闭，排查后点击“重试传感器”，或断开再连接重新启动。单纯松开微动不再重试激励。

新诊断中的“第N次激励启动”独立于书写笔画。为兼容已有20字节诊断结构，导出字段仍叫 `fault_stroke` / `power_stroke`，在v4代表激励启动编号；主遥测 `stroke` 是书写笔画编号，不能直接比较。电池窗口可能未取得开启前基线，此时明示缺失，不推算；长时间开启时采样计数字段饱和于255，但最低值继续更新。

姿态读取JY901S角度帧0x53，持续显示Roll/Pitch/Yaw；超过250ms无新角度会隐藏。固件只读波特率搜索，不改模块EEPROM/校准。要更快姿态显示，模块自身需输出足够快；建议至少10Hz，若需50Hz且同时输出加速度/陀螺仪，应自行使用模块配置工具配置足够波特率（例如115200），本次未擅自改模块。上位机遥测默认25Hz，因此可见姿态刷新不超过约25Hz。

按实际安装选择笔尖沿模块轴X/-X/Y/-Y/Z/-Z，归零只改变显示参考。姿态显示旋转方向，不通过加速度推算空间位置。各传感器用ESP32统一微秒时钟记录读取时间；不宣称物理采样已经毫秒级同步。

## 5. 电池电压、温度和充电

**电池电压可读。**板上 GPIO48 控制分压开关，GPIO1 读取 330kΩ / 330kΩ 分压。蓝牙主数据订阅后保持分压开启，先等150 ms稳定，再按约50 ms间隔各做8次读取平均；大字号电池显示仍约每秒更新一次。未连接时恢复间歇测量。换算为 `2 × ADC毫伏值`。若与万用表有偏差，在固件修改 `BATTERY_CAL = 万用表电压 / 显示电压` 后重烧录。

显示的是 VBAT 节点电压；USB 供电时，即使电池没有接上，充电芯片也可能使该节点有电压。软件不能仅凭这个电压确认电池是否存在，也不提供未经标定的电量百分比。

**现板不能读取具体电池温度。**J103 的 NTC 只连接充电芯片的 TS/MR，未连接 MCU 或 ADC。窗口明确显示“数值不可读”；不会拿 JY901S 内部温度或 MCU 温度冒充电池温度。电池温度探头仍发挥原有充电温度保护作用。

本版 `ALLOW_USB_CHARGING=true`：检测 USB 接入后允许硬件充电，不需要按按钮。该设置基于你已经确认电池反插问题已修复、J103 实装探头并贴在电池上。标称充电电流由现板 R104=5.1kΩ 决定，约 59 mA，软件不把它提高；系统负载和输入限流可能使实际充电电流更低。

| STAT1 / STAT2 | 窗口解释 |
|---|---|
| 高 / 低 | 充电中 |
| 高 / 高 | 完成、待机或被禁止，仅这两个状态脚无法细分 |
| 低 / 高 | 可恢复故障；温度、电压等均可能，不等于确定“温度异常” |
| 低 / 低 | 锁存故障 |

## 7. 指示灯、兼容与异常处理

- SYS/GPIO12：启动灯光结束后，10ms消抖后跟随微动，独立于BLE与GSR。
- FAULT/GPIO13：光学未就绪、IMU姿态过期、ADC错误或GSR故障。未连接IMU仍可能亮，不等于皮肤电必定失败。
- “重试传感器”：重置光学和ADC、重新进行激励检查；不会写JY901S设置。
- 主遥测v4与独立轨迹通道9006必须配套新版上位机。上位机能读旧v2/v3数据，但会提示更新；旧固件的微动控制规则不会自动改变。
- 找不到轨迹通道时，关闭旧程序、确认重烧录，重新扫描连接。健康数据能收到不代表轨迹通道已订阅成功。
- 光学通道超过200ms未到达时隐藏光标并断线；主遥测超过800ms中断时清空旧数据。超时后持续按着的同一笔不会被拼接，松开再落笔继续。
- 电脑事件队列溢出会明确报错并断开，避免显示不断积压的旧数据。板端队列满/积压时保留较新的数据，显示丢弃计数。

BLE为自定义GATT，不是蓝牙鼠标或经典蓝牙SPP；当前原型没有配对加密、绑定和应用鉴权。无CSV文件保存。Windows启动脚本保留，但本次原生UI在macOS测试。
